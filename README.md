Двухуровневый BVH (TLAS / BLAS)
    Зачем: Чтобы сделать систему подвижных объектов. Каждая модель (Сюзанна, Дракон) будет иметь свое неизменяемое дерево (BLAS), а при их движении мы будем перестраивать только крошечное верхнее дерево коробок сцены (TLAS). Процессор перестанет пересчитывать миллион полигонов каждую секунду.
Переход на вычислительные шейдеры (Compute Shaders)
    Зачем: Графический конвейер (Render Pipeline), который мы используем сейчас для вывода квада на весь экран, не позволяет эффективно передавать данные между этапами. Compute-шейдеры дадут возможность сделать многоэтапный рендеринг.
Система шумоподавления (Денойзер)
    Зачем: Чтобы убрать шум Path Tracing. Мы зафиксируем рендеринг на скорости 1 сэмпл на пиксель (чтобы получить высокий FPS даже на встройке Core Ultra), а специальный Compute-фильтр за 1–2 мс сгладит картинку до идеального состояния.
Статистика проверок пересечений лучей на GPU
    Зачем: Чтобы найти узкие места в BVH. Шейдер будет считать, сколько шагов обхода коробки сделал луч для каждого пикселя, и выводить на экран тепловую карту (красный — тяжело, синий — легко).
Оптимизация памяти BVH (Упаковка структуры в 32 байта)
    Зачем: Чтобы ускорить встройку процессора. Мы сожмем структуру BvhNode на GPU с 48 до 32 байт, спрятав служебные индексы в координаты .w векторов vec4f, избавившись от пустого мусора (padding) в памяти.
Очистка кода RayApp
